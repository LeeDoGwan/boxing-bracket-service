# 다국어 UI 설계와 유지보수

적용·검증일: 2026-10-10

## 지원 범위

- 한국어(`ko`), 영어(`en`), 일본어(`ja`)를 지원합니다.
- 최초 접속은 브라우저의 선호 언어 목록을 순서대로 확인합니다. 웹에서는 OS
  설정을 직접 읽을 수 없으므로 브라우저가 제공하는 `navigator.languages`를
  사용합니다. `en-US`, `en-GB`, `ja-JP`, `ko-KR`은 기본 언어로 대응합니다.
- 지원 언어가 목록에 없으면 한국어를 사용합니다.
- 상단 언어 선택에서 명시적으로 고른 언어가 자동 감지보다 우선합니다.
  `기기 언어 따르기`를 고르면 저장된 선택을 지우고 자동 감지로 돌아갑니다.
- 선택값은 `localStorage`의 `boxing.languagePreference`에 저장됩니다.
  계정 설정이 아니라 해당 브라우저·사이트의 설정이며, 다른 기기에는 전달되지
  않습니다. 저장소가 차단되어도 현재 탭의 언어 전환은 동작합니다.
- 관람 화면, 로그인, 심판, 감독관, 링 운영, 관리자 화면, 오류 안내와 확인창을
  대상으로 합니다. 사용자 작성 공지, 선수명, 소속, 경기 유형, 수정 사유,
  감사 로그의 원본 스냅샷은 번역하지 않습니다.

## 번역 코드 방식

요청한 코드 기반 조회 방식을 적용했습니다. 단어마다 숫자 코드를 붙이는 대신
`operations:score.red`처럼 의미와 사용처가 드러나는 키를 사용합니다.
단어를 이어 붙여 문장을 만들지 않고, 문장 전체와 삽입값을 번역 리소스에 둡니다.
이렇게 해야 영어·일본어의 어순을 독립적으로 조정할 수 있습니다.

```text
front/src/i18n/
  index.js                    언어 선택, 번역 참조, 날짜 표시
  LanguageProvider.jsx        React 및 document 언어 동기화
  errors.js                   기존 API 오류의 표시용 번역 매핑
  locales/
    ko/                       한국어
    en/                       영어
    ja/                       일본어
      common.json             공통 문구, 역할, 상태, 탐색
      audience.json           공개 현황, 대진표, 경기 상세
      operations.json         심판, 감독관, 링 운영, 모니터링
      admin.json              관리 화면과 감사 로그
      errors.json             오류 안내
```

`i18next`와 `react-i18next`를 사용하며, 리소스는 Vite 빌드에 포함합니다.
세 언어 규모에서는 초기 로딩 실패나 전환 지연 없이 사용하도록 전체를 묶습니다.
언어나 리소스가 크게 늘어나면 언어별 지연 로딩을 별도 검토합니다.
이는 번역 리소스의 로딩 방식일 뿐, 서비스에 오프라인 기능을 제공하지 않습니다.

```jsx
import { useTranslation } from 'react-i18next';
import { translate as t } from '../i18n';

function BoutTitle({ boutNumber }) {
  useTranslation();
  return <h2>{t('common:boutNumber', { value1: boutNumber })}</h2>;
}
```

React 화면은 `useTranslation()`으로 언어 변경을 구독합니다. 번역 함수는
모듈의 안정적인 `translate`를 사용하므로 데이터 조회 콜백의 의존성을 언어와
묶지 않습니다. 언어를 바꿀 때 재조회·입력 초기화·SSE 재연결을 유발하지 않습니다.
새 문구에는 `count`, `name`, `row`처럼 의미 있는 삽입값 이름을 권장합니다.
기존 문구를 옮긴 리소스의 `value1`, `value2`는 해당 키에서 정의한 순서를 따릅니다.

## 입력과 업무 상태 보존

언어를 바꿔도 페이지를 새로고침하거나 컴포넌트를 재생성하지 않습니다.
점수, 패널티 사유, 결과 수정 사유, 선택한 경기와 확인 대기 상태를 유지합니다.
이미 표시된 오류·성공 안내는 완성된 문자열 대신 번역 참조를 상태에 보관합니다.

```jsx
setError(localizedMessage('errors:score.range'));
// 렌더링 시 현재 언어로 해석합니다.
return <p role="alert">{resolveMessage(error)}</p>;
```

`localizedMessage` 객체를 React 자식에 직접 넣지 않습니다. 반드시
`resolveMessage`를 사용하거나 이를 처리하는 `StatePanel`에 전달합니다.
일반 사용자 데이터에는 이 처리가 필요하지 않습니다.

## API·DB·시간 계약

- DB 스키마, API 경로, 권한, enum, CSV 헤더 및 업로드 규격은 변경하지 않습니다.
- `RSC`는 전 언어에서 `TKO`로 표시하지만 요청에는 기존 `RSC`를 보냅니다.
- 승패 판단은 `RED`, `BLUE`, `DRAW` 코드로 처리합니다. 번역된 문자열이나
  선수 이름을 비교하여 판정하지 않습니다.
- API의 기존 `message`는 오류 진단용으로 유지하고, 화면에서 알려진 코드와
  HTTP 상태를 번역합니다. 알 수 없는 서버 내부 문자열은 그대로 노출하지
  않습니다. 가져오기 오류는 가능한 경우 행 번호와 필드 식별자를 유지합니다.
- 날짜 표시는 선택 언어의 `Intl.DateTimeFormat`을 사용합니다. 현재 국내 대회
  MVP의 표시 시간대는 `Asia/Seoul`이며, offset 없는 API datetime은 대회 현지
  시각으로 해석합니다. 언어를 바꿔도 경기 시각을 바꾸지 않습니다.
- 배포 서버가 생성하는 offset 없는 감사 시각도 같은 시간 기준이어야 합니다.
  해외 대회·다중 시간대를 지원하려면 API의 offset/timezone 계약부터 확장해야
  합니다. 이번 작업에서 서버 시간대나 데이터는 변경하지 않았습니다.
- 브라우저 기본 날짜 입력기, 필수값 안내, 파일 선택 창의 언어는 브라우저/OS가
  결정할 수 있으며 앱의 언어 설정으로 강제 변경하지 않습니다.

## 유지보수와 검증

1. 적절한 namespace에 의미 기반 키를 추가합니다.
2. 세 언어 파일에 같은 키와 같은 삽입값 이름을 추가합니다.
3. 버튼 제목뿐 아니라 접근성 이름, 오류, 빈 상태, 확인창도 번역합니다.
4. `npm run check:i18n`, `npm test`, `npm run lint`, `npm run build`를 실행합니다.
5. 긴 영어 문장과 일본어 문구를 모바일·태블릿에서 확인합니다.

`resources.test.js`는 키/삽입값 일치, 빈 번역, UI의 잘못된 키와 한국어
하드코딩 재유입을 검사합니다. 기존 CI의 `npm test`에 포함되므로 별도 워크플로는
필요하지 않습니다. 누락 시 런타임에는 한국어로 fallback하지만 CI에서는 실패합니다.

이번 검증: 28개 파일의 123개 테스트 통과. 언어 자동 감지, 명시 선택/해제,
저장소 제한, 다른 탭 동기화, 문서 언어, 날짜, 입력과 확인 상태 보존, 기존
서버 요청값 유지, 저장된 메시지 재번역을 포함합니다.

브라우저 확인 범위: 공개 오류 화면과 로그인 화면, 데스크톱 1280x900,
태블릿 768x1024, 모바일 390x844에서 언어 전환과 로그인 입력 보존 확인.
모바일 로그인 화면의 가로 넘침은 없었습니다. 백엔드는 실행하지 않았으므로
실제 계정/DB를 통한 업무 흐름과 모든 운영 화면의 기기별 시각 검증은 후속
통합 리허설 대상입니다. 일본어·영어 판정 용어는 실제 대회 관계자 감수를 권장합니다.

공식 참고: [React 언어 변경 구독](https://react.i18next.com/latest/usetranslation-hook),
[i18next fallback](https://www.i18next.com/principles/fallback).
